01 / WORKFLOW

先回答问题，再组织页面。

市场是否值得进入、收入增长为何没有变成利润、多个方向如何排序？Forge 从业务问题与决策约束开始，选择分析框架，查找证据、保留计算，再形成能够逐页追问的论证。

  1. 研究与分析

    核对来源、时期和口径；按问题选择市场测算、单位经济或情景分析。

  2. 形成故事线

    让每一页承担一个明确任务，让标题、证据和限制相互对应。

  3. 制稿与复核

    编译成稿，检查实际 HTML/PDF；复杂判断安排独立实例复核。

02 / IN PRACTICE

报告不仅要成形，也要经得起阅读。

实际成稿与布局工作台展示了两种能力：解释复杂证据，以及安排足够清楚的阅读层级。每个图表的来源、期间与限定需要继续保留。

03 / OVERVIEW

材料更新后，知道哪些地方需要重查。

持久执行清单记录任务与恢复线索。内容和展示值变化会影响原审查的有效性；局部排版修订按证据确定重审页。模块填充检查同时关注大块无功能留白、裁切和溢出。

04 / GET STARTED

从一份经营分析开始。

先安装完整技能和所需依赖，再提供材料、预算、业务口径与停止条件。完整制作通常需要 Node.js、Python、浏览器和 PDF 检查工具。

示例任务

使用 zerox-consulting-report-forge 制作经营分析报告。读者为经营团队，回答未来两个季度应优先投入哪些渠道；保留来源、假设与计算，交付中文 HTML + 同版 PDF。
05 / SCOPE & BOUNDARIES

独立作品，持续在合集里维护。

原 consulting-report-forge 仓库保留历史版本；当前技能名为 zerox-consulting-report-forge。它交付 HTML/PDF，不输出可编辑 PPTX，也没有独立在线编辑器。质量取决于材料、模型和实际复核，不承诺固定时间或普遍提速。
