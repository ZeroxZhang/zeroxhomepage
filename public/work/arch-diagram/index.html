01 / OVERVIEW

让架构图经得起评审，而不是让评审先猜图

架构图常在细节处失去可信度；这套 Skill 把画图决策写成可以检查的契约。

架构图最容易在细节处失去可信度：节点看似整齐，跨层连线却互相遮挡；箭头从含义含混的方向进入；标签压住路径；容器与泳道无法说明组件的归属。结果往往是——评审先猜图，再讨论系统，图也很难随着设计继续演进。

Architecture Diagram 是一套面向 Agent 的架构图生成 Skill。它把拓扑、分层、端口、路由和验收写成明确契约，使一张图从关系模型出发，最终交付为可以阅读、检查和继续编辑的 HTML 与 SVG。

生成前，Agent 先区分拓扑、视觉泳道、容器、节点、端口与边，并用稳定 ID 建立布局计划。端口方向和连线通道在节点放置阶段就被预留，减少后期硬塞路径造成的交叉与误读。

接入层、应用层和数据层可用泳道表达位置语义；前端、后端、数据库、云服务等组件则通过一致配色表达类别。Structure Model

02 / CAPABILITIES

先算清楚结构，再画出图形

从关系模型出发，把布局流程与交付物分别做成可检查的步骤。
02.1 / 先算结构

先把关系变成可计算的结构

布局流程依次处理文本测量、排序、打包、放置、正交避障路由、标签占位和边界计算。节点 bbox、route、lane、group 与 z-order 会保留在语义化 SVG 中，后续脚本可以检查几何关系，而非仅凭截图目测。

02.2 / 两份交付物

从需求到两份可继续使用的交付物

HTML 适合直接浏览、展示摘要卡片和悬停提示；SVG 可嵌入文档、网页或演示文稿。亮色、暗色与 1280×720 演示模板覆盖常见传播场景，产物不依赖远程字体、图片或脚本，离线也能打开。

当架构发生变化时，可以沿用同一组节点与边的 ID 更新关系，再重新执行提取和校验，减少手工改图后遗漏标签、箭头或边界的风险。

03 / USAGE

从需求到交付，每一步都可检查

典型生成从需求描述开始，中间产物可以回看，改图不必整张重来。

一次典型工作从主题、语言、方向、泳道和展示范围开始。Agent 先规范化关系图，再生成稳定 ID 的 ASCII 布局计划，随后输出包含内联 CSS 与 SVG 的完整 HTML；仓库脚本再从 HTML 精确提取独立 SVG，并对两份文件执行结构、边界和一致性检查。
