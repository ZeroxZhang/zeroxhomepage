01 / OVERVIEW

论文为同行而写，课程为学习而设计

从「论文说了什么」走到「为什么这样成立」。

对第一次接触主题的读者来说，困难未必来自概念本身，而是论文没有为学习设计路径。

学术论文服务于同行交流。它需要在有限篇幅里报告方法、实验和贡献，因此会省略大量背景，也常把关键推导压缩到几个公式之间。

摘要擅长提取结论，却很少处理理解过程。读者仍然需要自己查背景、补公式、追溯前人工作，并判断伪代码中的每一步在做什么。

课程把理解过程变成可见动作：公式分段展开、算法逐行高亮、研究关系画成谱系、理解用练习验证。Learning Interface

01

识别研究问题、核心贡献、方法、实验与限制，建立事实底稿，避免课程为了通俗而改变论文原意。

02

补充前置概念、历史背景和相关工作，区分论文原文与外部解释，让读者知道每个结论来自哪里。

03

确定学习目标、章节顺序和交互点。只有确实能降低认知成本的内容才进入交互，不要求把所有元素都用一遍。

05

Boundary / 适用边界

对公式密集、算法复杂、历史脉络重要的论文尤其有价值；对于结构简单、已有优秀教程的材料，完整课程生产可能不划算。

它不会替读者保证理解，也不能自动验证所有扩展资料——作者仍需检查学术准确性、版权边界和引用。

一种面向学习动作的写作方式

如果只是想快速提取结论，摘要已经足够。paper-to-course 面向的是另一种需求：你真的想把一篇难论文读懂，并且希望这个过程可以被保存、分享和反复使用。

这套方法后来用于 Zerox Agent Course 与 Nanobot Course，把学习对象从论文扩展到代码库。共同原则保持不变：先设计理解路径，再选择页面和互动。
