01 / OVERVIEW

从收藏仓库，走向一条能反复使用的内容循环

笔记数量不等于知识积累；IO System 把「以后怎么用」的判断前移，并保存成明确结构。

收藏工具解决了「先存下来」，却很少解决「以后怎么用」：链接进了稍后读，摘录散落各处，灵感失去上下文，等到开始创作，仍要凭记忆找来源、重建关系，并判断哪些旧材料值得重新打开。

IO System 是一套运行在本地文件与 iCloud 上的个人内容系统。它把输入、来源、主题、输出和再发现连成同一条工作流，使素材有来路、成品可追溯、旧内容能够再次参与创作。Markdown 保存正文，YAML 描述关系，Python CLI 执行约束；文件系统始终是唯一事实源。

系统以内容在不同阶段之间的流动为核心：一段输入如何成为观点，一份输出如何保留证据，完成的文章又如何变成下一轮创作的材料。单篇笔记只是这条链路中的一个载体。

这些判断不依赖某个应用的私有数据库：来源关系可以直接检查，索引也可以从文件重建。Local-first / 事实源

02 / CAPABILITIES

五个相互衔接的层次

类型、来源、主题、再发现与审计，各自解决一类「内容用不起来」的问题。
Layer 01 / Input

输入有类型，也有归属

idea、material、snippet、spark 描述当前状态；六类自然语言意图覆盖输入、输出、灵感、剪藏、归档和系统命令。含糊指令先询问，不替用户猜测。

Layer 02 / Sources

来源关系随内容一起保存

每份输出用 sources 字段连接原始材料、历史输出和外部来源，成品可追溯，旧文也能成为新项目的输入。

Layer 03 / Topics

主题词表控制长期漂移

规范名称与别名统一登记，避免同一概念因大小写、缩写或中英文表达不同而形成多个孤岛。

Layer 04 / Spark

Spark 负责再发现

随机考古、跨主题连接、标签扩展、时间脉冲和矛盾发现，从旧材料里找新组合，并按采纳调整权重。

Layer 05 / Audit

审计维护系统健康

rebuild-index 从文件重建索引，audit 检查元数据、引用关系和目录结构；索引是可重建的派生视图。

Foundation / Local-first

文件是唯一事实源

正文与关系留在可读文件里，索引可以重建，内容不会锁进某个应用的私有数据库。

02.1 / Source Relationships

来源关系随内容一起保存

每份输出通过 sources 字段连接原始材料、历史输出和外部来源。成品可以一路追溯到依据，旧文章也能成为新项目的输入。

这些关系不依赖某个应用的私有数据库，可以直接检查，也可以由脚本审计。来源因此不再停留在写作时的记忆里，而是成为内容的一部分。

内容可以离开工具，关系经得起审计——这是「local-first」在 IO System 里的具体含义。

02.2 / Audit

审计维护系统健康

rebuild-index 可以从文件重建索引，audit 检查元数据、引用关系和目录结构。索引属于可重建的派生视图。

即使工具发生变化，作为事实源的正文和关系仍留在可读文件中。系统的健康不依赖某个应用是否还在维护。

03 / WORKFLOW

一条真实的内容流

系统价值由这条链路能否连续运转来衡量，界面里保存了多少卡片只是表面规模。
Representative Flow / 典型内容流5 Steps
01SILENZIO 转录播客 → 02material 入档 · 记录来源与主题 → 03Spark 发现与旧摘录的矛盾 → 04进入草稿 → 05输出保留 sources

一段播客先由 SILENZIO 转成文字，其中值得保留的观点以 material 进入 IO System，并记录节目来源与主题。后来准备文章时，Spark 找到它与另一份旧摘录之间的矛盾；两者共同进入草稿。文章完成后，输出文件仍保留 sources，日后还可以被拆成短内容或成为新研究的入口。

03.1 / Agent Participation

Agent 如何进入这套系统

IO System 不把 AI 当成拥有独立记忆的黑箱。Claude Code、Codex 或其他执行环境需要遵守同一套目录、schema、命名和确认规则。Agent 可以帮助归档、建立来源关系、生成 Spark 或执行审计，但内容边界和事实源不会因为更换模型而改变。

风格文件则把「写成什么样」从单次提示词中抽离出来。开始生成前先选择对应语气和用途，减少不同工具接入后造成的表达漂移。规则本身与内容一起版本化，能够被检查和修订。
