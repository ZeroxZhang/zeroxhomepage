# 面向市场的产品介绍页内容逻辑调研

调研日期：2026-08-22
调研目标：找出能让潜在用户快速理解价值、产生欲望并采取行动的产品介绍页叙事结构，用于重写个人网站全部作品详情页。

## 关键问题

1. 顶级产品页如何在首屏完成定位、价值承诺与行动引导？
2. 页面如何排列问题、转变、利益、功能、证据、异议与 CTA，才能持续增强购买或使用意愿？
3. 软件、内容产品、研究工具、实验项目如何共享统一内容骨架，同时保持各自的产品气质？
4. 如何把可信边界放在正确位置，既不夸大，也不让说明性文字压过产品价值？
5. 内容模型如何与未来前端组件解耦？

## 发现

### 第一轮：Apple、Linear、Stripe 的页面编排

- Apple 的页面不是从芯片参数开始，而是先用可复述的利益标题建立欲望，如“全天续航”“为 AI 而生”；参数紧跟在对应利益之后，负责证明承诺，而不是主导叙事。页面后段再处理选型、交付、支持与环境信息。
- Linear 的迁移页先命名市场变化：个人因 AI 变快，协作反而成为瓶颈。产品随后作为“现代产品开发系统”出现，形成“旧世界失效 → 新游戏出现 → 产品带你进入新世界”的战略叙事。
- Stripe 把商业结果置于功能之前：先承诺减少结账摩擦、提升收入、节省工程时间，再用 11.9% 收入提升、100+ 支付方式、交互演示和客户证言完成证明。
- 三者共同使用“利益标题 + 使用场景 + 机制 / 数字证据”的三层表达。孤立功能列表很少承担主叙事。
- CTA 在首屏、段落节点与结尾重复出现；每次 CTA 都对应读者当下已经建立的信心，不依赖读者读完整页后自行寻找入口。

### 第二轮：Raycast 与 Notion 的欲望、场景和信任设计

- Raycast 先用一句可占据心智的定位“通往一切的快捷方式”，再把“省时间”提升成更有情绪价值的“感觉自己从未浪费时间”。这比“一个可扩展启动器”的品类说明更能制造欲望。
- Raycast 不逐条解释架构，而是让访客连续想象具体动作：不打开应用就更新 Linear、搜索 Notion、控制 Spotify、复用片段。能力通过“我马上会怎么用”被理解。
- Raycast 把性能指标（毫秒级、99.8% 无崩溃）和专业用户背书放在主承诺之后，形成理性确认；结尾“走捷径”回扣首屏隐喻，并再次给出下载入口。
- Notion 用三个结果型动词组织复杂产品：捕获知识、找到答案、自动化杂务。下层功能再归入这些用户任务，避免庞大功能集失焦。
- Notion 把客户案例、用户规模、行业排名与安全承诺放在功能体验之后、价格和 FAQ 之前，依次回答“有用吗、别人信吗、适合我吗、风险是什么”。
- 两者都把技术名词翻译成用户可感知的变化：不是“提供某能力”，而是“无需切换工具”“工作 24/7 继续推进”“更少追踪，更多进展”。

### 第三轮：定位与客户主角原则

- April Dunford 把定位定义为：产品相对替代方案，为某类最匹配客户提供何种差异化价值。页面文案必须先完成这个选择，不能用一套泛化形容词覆盖所有访客。
- StoryBrand 的核心约束是“客户是主角，品牌是向导”。主角想得到某个结果、遇到阻力、获得一套可执行方案，并被清晰 CTA 推向成功；创作者的开发过程只在能增强信任时出现。
- Andy Raskin 的战略叙事不是从“我们做了什么”开始，而是从世界正在发生的变化开始，解释旧方法为什么失效，再给出新世界的赢法。
- 三套方法可以组合成适合本项目的顺序：先用市场变化或高压场景抓住注意力，再给出针对明确人群的差异化承诺；把读者放入“使用后的更好状态”，最后用机制和证据消除怀疑。

### 阶段摘要（第 3 轮）

顶级产品页不是一篇项目说明书，而是一条信心逐步上升的决策路径：**五秒定位 → 痛点 / 变化 → 理想结果 → 利益化能力 → 体验与证据 → 适配与异议 → CTA**。技术、过程和限制不是删除，而是被重新安排到服务购买决策的位置。

## 调研结论

### 统一内容角色

每个作品页统一七种内容角色，但标题必须按产品单独创作，不能机械复用“核心功能 / 技术实现”：

1. **五秒承诺**：一句话说清给谁、带来什么变化；首屏直接提供主 CTA。
2. **高压场景**：让目标用户认出自己正在失去的时间、控制、注意力或机会。
3. **新方式**：用一句可复述的观点说明旧方法为何失效，这个产品相信什么。
4. **结果型能力**：每项能力按“利益标题 → 真实场景 → 产品机制 → 用户结果”展开。
5. **低摩擦路径**：用 1–3 步说明如何开始，让用户能想象第一次成功。
6. **信任与适配**：用版本、测试、案例、公开仓库、边界说明回答“可信吗、适合我吗”。高风险声明在这里明确呈现，但不抢占首屏。
7. **成功画面与 CTA**：回扣首屏承诺，描述行动后的状态，只保留一个主要动作。

### 写作约束

- 页面主语优先使用“你”，产品其次，创作者最后。
- 每个区块必须回答“所以用户能怎样”，不能停在组件、协议、模型或技术栈。
- 每页只争夺一个心智位置；不能同时把产品写成平台、工具、作品、实验和方法论。
- 先写可想象的场景，再给抽象形容词；先给价值，再给原理；先给主路径，再给完整能力。
- 事实证据越具体越好；没有数据时用可验证机制，不虚构用户评价、收益或效果。
- 风险项目明确注明“辅助判断 / 教育 / 演示”，但不使用大段防御性语言破坏叙事。

### 前端适配建议

- frontmatter 保留稳定字段，作为首屏、卡片与 CTA 的结构化数据；正文只负责叙事区块。
- 页面模板按内容角色渲染，不依赖固定中文标题；未来可通过可选字段给不同产品启用演示、指标、对比、FAQ 等组件。
- 首页卡片复用 `tagline`、`summary` 与唯一的 `primary: true` 主链接；详情页不应要求前端从正文猜测 CTA。

### 全量改写后的校准

- 七种内容角色用于约束信息顺序，不作为固定章节标题。35 个页面按 `flagship`、`featured`、`standard`、`compact` 四个层级控制展开深度，每个层级都保留独立详情页所需的完整叙事。
- schema v2 在同一作品文件中保存完整中文与英文。英文按英文产品网站的阅读习惯重新组织，必须覆盖相同的定位、能力、事实和责任边界，不能缩成中文页摘要。
- 扩写优先增加真实使用流程、产品机制、设计取舍、公开证据和限制。缺少数据时保持空缺，不用虚构案例、泛化收益或重复卖点补足篇幅。
- 专业语气来自准确名词、具体动作与证据口径。终稿需专项删除高频模板句、连续反问、抽象口号和无依据的程度形容词，特别检查“不是……而是……”“真正”“赋能”及英文营销套话。
- 中英文正文在前端解析前按 locale marker 切分；首页卡片、SEO 与 CTA 使用同 locale 的 frontmatter 字段。详细契约以 `content/works/README.md` 与 `docs/specs/2026-08-21-portfolio-content-model.md` 为准。

## 待确认问题

- 部分作品尚无真实用户评价或量化转化数据；这些页面只能使用已核验的版本、测试、部署状态与机制作为证据。
- 未来若加入购买、订阅或预约入口，需要为相应产品补充价格、交付方式、退款 / 支持与 FAQ。

## 写作建议

- 先重写首屏三件套（`tagline`、`summary`、主 CTA），再写正文；如果首屏不成立，正文无法补救。
- 旗舰项目使用完整七段式，精选项目压缩为五至六段，标准与轻量项目保留四段，但内容角色和决策顺序不变。
- 每页至少有一个产品专属的“可复述句”，避免 35 页读起来像同一个模板批量生成。
