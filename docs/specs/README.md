# specs/ - 技术方案

本目录记录跨文件或跨系统、仅靠代码局部上下文不容易看清的技术契约与取舍。

PRD 主要描述目标与约束，spec 说明当前打算怎样实现以及哪些接口或不变量需要共同遵守。

## 原则

- 只固定对协作、兼容性、数据完整性或风险控制真正重要的内容，给局部实现保留选择空间。
- 明确哪些是已采用决定、建议实现、开放问题和未来扩展，不把示例误写成唯一解。
- 实现验证可以修正 spec。出现偏差时判断是代码缺陷还是设计演进，再更新对应一侧。
- 对简单且可由类型、测试或代码清楚表达的设计，不强制额外写 spec。
